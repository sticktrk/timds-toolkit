Paste one address

For a one-off, hand any AI tool that can read a URL the system's llms.txt. The file opens with how to use itself, then the brand essentials: every role color, every font and where it comes from, every logo, every asset format, and the directory of these pages. Paste the line below into the chat and finish it with the work you want.

Read https://THIS-SYSTEM/llms.txt and follow it. Then: …
AddressHoldsUse it when
llms.txtHow to use the file, the brand essentials, and the page directory with a link to each page's Markdown.Most one-off work. The tool follows a link only for the detail it needs.
llms-full.txtEvery page's Markdown in one file.A tool that reads a single URL and cannot follow links, or work that touches the whole system.

Both files are regenerated on every release and carry absolute addresses, so either one can be handed around on its own. Nothing is installed and nothing is pinned: the next paste reads the next release. Ask the tool to name the version it read; it is on the file's first lines.

Connect your agent over MCP

For ongoing work in a repository, add the system's read server to the agent once. Snippets 1 to 6 run the TimDS CLI at @latest against this public copy, with no sign-in or token: the server reads the derived layer and never edits authored source. An installed binary can instead run timds-cli mcp read --published URL with this system's public URL. It is named timds-design-system-read; its first calls are get_consumer_guide, then describe_system, and system reads name the release they read. Pick the tool, copy the snippet, and start a new conversation in the repository.

Snippets 1 to 6 give the agent the whole consumer tool set: brand roles, tokens, guidance search, pages, formats, designs, and media; Compose lists every tool. If you use TimDS Cloud, snippet 7 needs no local CLI when the host exposes that endpoint. Discover its advertised tools before calling them; the host may offer describe_system, get_tokens, read_page and read_derived_layer, each taking this system's id, SYSTEM-ID, as systemId and an optional version. Historical selection depends on the host; a local or fixed-URL reader uses version only to assert its served release.

For the toolkit read server, first reads in order: get_consumer_guide once per conversation, then describe_system and note the version. For a color or a font ask resolve_role, not a token name; for marks and imagery get_brand and list_media; for copy search_guidance; for a size list_formats. Report what was used, and name anything the system could not answer rather than guessing it.

When the release is an offshoot, describe_system and the derived layer's provenance carry lineage: its parent system, source, release, commit, and creation mode. A null lineage is supported for ordinary systems and older releases. Ancestry describes where the system began; use the served system's guidance and assets.

Pin a release in a website or app

A product never copies the system. One command at the product's root pins the current release in timds.consumer.json, wires a digest-verified fetch of the consumer bundle into npm install, installs timds-consume-design-system for design changes and timds-update-design-system for developer pin updates, and writes launch and review configuration. It also registers the hosted read-MCP entry, which needs host authorization when used. A clone and an install is then all a developer, or an agent working in the product, needs.

npx --yes @dtconcepts/timds@latest consumer init --system SYSTEM-ID --url https://THIS-SYSTEM
npm ci
ThenCommandDoes
Move the pinnpm run timds -- consumer updateMoves to the current release, or to the version named after it. A pin of current follows every release at the next install.
Checknpm run timds -- consumer check --base REFValidates the manifest and the pin, and that a branch stays inside the product's declared design surface.
Reviewnpm run timds -- consumer preview --app NAMECaptures the configured routes, widths and schemes. Paired design captures need a Design System checkout or symlink; a published bundle shows the product routes only.

Replace REF with the review base, such as origin/main. Run from the product root using its selected toolkit. For this system's own site, consumer scaffold emdash --workspace writes site/ under its Design System root with no pin; follow the site's installed consumer skills and run its own check and build. The pinned-product commands above apply to separate products. Binary consumers use timds-cli instead of npm run timds -- and explicitly run timds-cli consumer sync to fetch the pin; keep the product's own install/build commands. In product CSS use a token by name, never by its literal value, so the product follows the pin. SYSTEM-ID is this system's id, the one .timds-artifact.json beside this page names; a browser fills it in above. Compose has the full product workflow.

Give your agent the designer skills

This published copy is read-only. To change a local or Git system, open its repository and follow its AGENTS.md and installed design-start skill; init and upgrade manage those skills. If you use TimDS Cloud, install the hosted skills with the command below from a separate working folder, outside any Design System, consumer repository or session. That skill signs in, starts or joins a session, opens the local preview and submits for review when you ask.

npx --yes @dtconcepts/timds@latest skills install --portal-url https://YOUR-HOST --system-id SYSTEM-ID

The skills land in .agents/skills/, .claude/skills/ and .cursor/skills/; --global puts them under the home folder instead. YOUR-HOST is the host's authenticated origin, not this public address: Studio's Send your agent… button produces a brief with it filled in. Compose covers the other ways the system changes.

Stay current

Public reads follow the release at their configured address. Products pin a Design System release and an exact toolkit resolution in their lockfile or binary installation record. Moving either selection is an explicit update; a new publication does not silently move a product's pin.

Way inOn a new release
One addressNothing to do. The files are regenerated with each release.
An agent over MCPThe fixed-URL server reads the release at that address; version asserts that release. Selecting an earlier release is available only when the connected host supports it.
A pinned productMove the pin with consumer update when the developers are ready; the changelog lists what changed in between.
Designer skillsIn a repository, use its selected toolkit's upgrade. In a separate skills folder, rerun skills install; it refreshes unmodified files and keeps edits.
