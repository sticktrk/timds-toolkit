Components

Each component is a live preview and the rules for using it. The class names and the markup to copy sit folded under each one, so the page reads as the brand first and as code only when you open it.

Buttons

A button starts an action. A link that only navigates stays a link. One view has one primary action; every other action is secondary and sits beside or below it.

Spec
VariantClassUse
Primary.buttonThe one action a view exists for; at most one per view
Secondary.button.button--secondaryEvery other action beside or below the primary
 
<button class="button" type="button">Primary action</button>
<button class="button button--secondary" type="button">Secondary</button>

Form fields

A field is a label, a control, and optional help text, in that order. The label is always visible; a placeholder is not a label. The control is tall enough to hit on a touch screen, and help text is one sentence directly under it.

Spec
PartElementRule
LabellabelAlways visible and tied to the control with for; a placeholder is not a label
ControlinputAt least 3rem tall so it is easy to hit on touch screens
Help textsmallOne sentence directly under the control
 
<div class="field">
  <label for="email">Email address</label>
  <input id="email" type="email">
  <small>Keep help text close to the control.</small>
</div>

Site layout

The pieces a whole page is composed from: a header with the brand and the navigation, a hero that opens the page, a section for each further band, a form and a notice where a page needs them, the article list and the body of an article, and a footer. The website design under Designs shows them assembled and uses nothing else, so a page needs only these and the components above.

Spec
PieceClassUse
Wrap.wrapCenters a band of the page at the content width with side gutters; the header, main content, and footer each sit in one
Site header.site-header, .site-header__brand, .site-navThe brand link and the site navigation at the top of every page
Hero.heroThe opening band: one heading, one paragraph, then the actions
Section.sectionEach further band of a page, with a heading and short copy; give it an id so the page can link to it
Form.formStacks fields and their submit button
Notice.noticeA confirmation or status message in its own panel
Article list.article-list, .article-cardThe list of articles, one card per article with its optional cover image, title link, summary, details, and topics
Article meta.article-metaThe date and byline line of an article or a card
Topic list.topic-listThe topics an article is filed under, each a link to its topic page
Prose.prose, .table-scrollWraps an article's body; headings, paragraphs, links, lists, quotes, code, figures, and tables inside it carry no classes, so rendered rich text needs only this one, plus the wrapper that lets a wide table scroll
Site footer.site-footer, .site-footer__linksThe closing line of every page, with the links to the legal pages
Stylesheet. Every class above is styled in /styles/system.css, the one stylesheet a product loads.
